## **Categories Explained**

### **Mathematical Visualizations**
These explore mathematical structures rendered visually:
- **collatz.html** — Collatz 3n+1 sequences in golden-angle spiral
- **culmination.html** — Convergence points and attractors
- **cortex_overload.html** — Complexity escalation (fractal depth)

**Why these matter:** They validate that chaos can be beautiful when visualized procedurally.

---

### **Music Theory Explorations**
These test different musical styles and synthesis approaches:
- **bach.html** — Classical/baroque (complex harmony)
- **beatles.html** — Pop/acoustic (simple, memorable)
- **alexa.html** — Experimental (breaking traditional rules)
- **alma_gitana_flamenco.html** — Rhythmic complexity

**Why these matter:** Each tone recipe and rhythm pattern teaches about music synthesis.

---

### **Atmospheric / Ambient**
These prioritize mood over structure:
- **creation_trance.html** — Meditative, slow, hypnotic
- **climbing_mountain.html** — Progressive energy buildup
- **ethereal_*.html** — Variants of ethereal/spacey effects

**Why these matter:** Shows how procedural synthesis can evoke emotion.

---

### **Artistic / Abstract**
These prioritize aesthetic and emotional impact:
- **anatolian_wolf.html** — Intense, primal
- **archangel.html** — Celestial, transcendent
- **anthropos.html** — Philosophical, humanity-focused

**Why these matter:** Proves that abstract procedural art has legitimate artistic value.

---

### **Technical Studies**
These are testing/debugging:
- **performance_demo.html** — Particle count impact on FPS
- **browser_test.html** — Cross-browser audio API support
- **compatibility_*.html** — Testing specific features

**Why these matter:** Ensure the framework works reliably.

## **Archiving Notes**

This folder contains many duplicates and iterations (e.g., `ai_studio_code (14).html` through `ai_studio_code (40).html`). These represent:
- **Rapid prototyping** — Iterating on a single concept
- **Parameter sweeps** — Testing how tweaks affect output
- **Exports from tools** — Generated filenames suggest batch generation

## **Contributing**

When adding new simulations to `second/`:

1. **Use snake_case** naming: `my_new_sim.html`
2. **Add a brief comment** at the top of the file explaining its purpose
3. **Update this README** with the file in the appropriate category
4. **Test in multiple browsers** (Chrome, Firefox, Safari)
